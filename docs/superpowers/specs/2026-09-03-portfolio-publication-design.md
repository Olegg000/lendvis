## 2. Адресная схема

Организация `lendvis`, хаб живёт в репозитории `lendvis/lendvis.github.io`, на него вешается `lendvis.ru`.
GitHub отдаёт проектные Pages той же организации на том же домене, поэтому все статические демо
получают адреса вида `lendvis.ru/<repo>/` без единой дополнительной настройки.

**Статика — GitHub Pages (апекс + www):**

```
lendvis.ru                          хаб
lendvis.ru/screenplay-to-shotlist/  Shot List
lendvis.ru/react-bugfix-demo/       разбор багов
lendvis.ru/hr-connect/              Swagger-документация mock API
lendvis.ru/python-faq-bot/          витрина бота записи
lendvis.ru/alice-smartlight/        умный дом
lendvis.ru/blockchain-practice/     мультичейн-практика
lendvis.ru/vps-setup/               автонастройка сервера
lendvis.ru/hotel-booking/           \
lendvis.ru/hr-assistant/             > страницы четырёх мобилок: кадры, описание, ссылка на APK
lendvis.ru/atelier/                 /
lendvis.ru/arena/
```

Первые семь адресов — уже собранные Pages, переезжают вместе с репозиториями.
Четыре последних создаём: сейчас у мобилок нет ни страницы, ни релиза.
Работы без демо (`fabric-supply-chain-ts`, `waves-enterprise-integration`, `alice-skill-demo`,
`allTogether`, `volgaIT2025-flutter`) живут страницей на хабе и ссылкой на код — отдельный
адрес им не нужен.

**VPS Timeweb — поддомены под то, где нужен живой процесс:**

```
board.lendvis.ru    drawer: Node + Socket.IO — совместное рисование в реальном времени
quiz.lendvis.ru     quiz: Express + PostgreSQL — полноценная LMS с ролями
api.lendvis.ru      сам mock API (чтобы в Swagger работала кнопка «Try it», а не только чтение)
                    + вебхук навыка Алисы: Яндексу нужен настоящий HTTPS-эндпоинт
mail                MX почты домена
```

Причина разделения не в экономии. Два демо сейчас показывают половину продукта:
у `drawer` на статике работает только локальный режим — то есть совместность, ради которой
проект и сделан, не видна; у `quiz` демо отвечает записанными фикстурами вместо живой базы.
VPS чинит ровно это. Остальные одиннадцать статических сборок на VPS не выигрывают ничего,
а стоят двух десятков деплой-пайплайнов и собственного аптайма: если хост ляжет во время
визита заказчика, тёмным станет всё портфолио разом, а не одно демо.

DNS ведём в Timeweb: апекс — четыре A-записи GitHub Pages, поддомены — A на VPS, MX на почту.

Побочный выигрыш от собственного домена: у хаба уходит `/lendvis/` из base-пути и можно снять
HashRouter. Адреса `lendvis.ru/#/work` становятся `lendvis.ru/work` (на Pages — копией `index.html`
в `404.html`). Это одновременно вопрос вида ссылок и индексации.

## 3. Стоимость переезда, названная честно

GitHub переносит репозиторий вместе с редиректами, но **Pages редиректы не наследует**.
В момент переноса все живые адреса `olegg000.github.io/*` умирают безвозвратно.
Поэтому перенос делается **до** того, как адреса вошьются в двадцать пять README, OG-теги,
sitemap и подписи — иначе эта работа делается дважды.

Все публичные ссылки пишем сразу как `lendvis.ru/...`. Между переносом и покупкой домена
они несколько дней не отвечают — это допустимо: портфолио ещё нигде не анонсировано,
переходов по нему нет. Публикация и анонс — только после переключения DNS.

`Olegg000/FlipCoin` остаётся публичным и обязан остаться: on-chain метаданные живого жетона
